# Growth Hacker App - Business Stage Analysis Engine

## Overview
This system analyzes any business URL and outputs:
1. Business Archetype (HVP / EBP / PEH)
2. Current Growth Stage (0-10, 10-50, 50-100, 100-250, 250-500)
3. Stage-specific: Concern, Actionable Insight, Next-Step Actions, Red Flag

## System Requirements

### Backend
- Python 3.11+ (recommended) OR Node.js 20+
- PostgreSQL 15+ (or Supabase)
- Redis (for caching)
- Docker (optional, for containerization)

Database Schema

Table: brands

CREATE TABLE brands (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  url TEXT UNIQUE NOT NULL,
  name TEXT,
  archetype TEXT, -- 'HVP' | 'EBP' | 'PEH'
  core_unit TEXT,
  estimated_stage TEXT, -- '0-10' | '10-50' | '50-100' | '100-250' | '250-500'
  created_at TIMESTAMP DEFAULT NOW(),
  updated_at TIMESTAMP DEFAULT NOW()
);

Table: analyses

CREATE TABLE analyses (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  brand_id UUID REFERENCES brands(id),
  raw_data JSONB, -- scraped data
  classification JSONB, -- archetype + stage + reasoning
  playbook JSONB, -- concern, insight, actions, red_flag
  created_at TIMESTAMP DEFAULT NOW()
);

Table: cache

CREATE TABLE cache (
  url TEXT PRIMARY KEY,
  response JSONB,
  expires_at TIMESTAMP
);

Implementation Steps

Phase 1: Data Ingestion

Use Playwright to load the URL with JavaScript rendering
Extract:
<title>, <meta description>
All <h1>, <h2>, <p> text content
Pricing information (look for "$", "₹", "€", "/mo", "/month", "per")
Client logos (look for <img> with alt text containing "client", "partner", "logo")
Testimonials (look for blocks with "testimonial", "review", "said")
Navigation links (to detect /pricing, /solutions, /retreats, etc.)
Use Trafilatura to extract clean, readable text
Phase 2: Classification

Run @knowledgesdk/mcp.classify_business(url) or equivalent
Run heuristic rules engine:
Check for pricing visibility → HVP vs EBP
Check for keywords: "retreat", "healing", "escape" → PEH
Check for enterprise keywords: "enterprise", "compliance", "banking" → EBP
Check for self-serve keywords: "start free", "sign up", "pricing" → HVP
Estimate stage:
Count client logos → 0 = 0-10, 1-5 = 10-50, 5-20 = 50-100, 20+ = 100-250
Check for "500+" or "100+" claims → 250-500
For PEH: check booking availability + review count
Phase 3: Playbook Generation

Load the Stage Matrix JSON (embedded in code)
Fetch the entry for { archetype: X, stage: Y }
(Optional) Pass the raw data + matrix entry to an LLM for personalization:
Prompt: "Given this brand data [raw_data] and this stage playbook [matrix_entry], personalize the concern, insight, actions, and red flag specifically for this brand's industry and audience."
Return the enriched playbook
Phase 4: Caching

Cache analysis results for 7 days per URL
Use Redis for faster lookups

## Summary: Quick Reference Table

| Layer | Recommended Tool | Why |
| :--- | :--- | :--- |
| **Scraping** | Playwright + BeautifulSoup + Trafilatura | Free, handles JS, clean text extraction |
| **Classification** | Heuristic Rules + @knowledgesdk/mcp | Rules are deterministic; MCP adds ML backup |
| **Stage Detection** | Custom Rules Engine (client logos, testimonials, claims) | Most reliable; no external API dependency |
| **Playbook Generation** | Stage Matrix JSON + (optional) Ollama/LLM | Matrix gives 90% accuracy; LLM adds personalization |
| **Database** | Supabase (PostgreSQL) | Free tier, built-in auth, real-time |
| **API** | FastAPI | Fast, async, auto-docs |
| **Cache** | Redis | Industry standard, fast |
